# v0.4 遊べる1夜の縦切りスライス 設計メモ

## 目的

現在の KEBAB AFTER DARK は、`title -> radio -> exploration -> prep -> sales -> meatTower -> morning -> radio` の画面遷移が通る基盤です。v0.4 ではこの遷移を壊さず、1夜の中で「探索の判断」「素材選択」「ケバブ性能」「客との相性」「肉タワー成長」「翌朝ログ」が数値としてつながる状態にします。

このメモでは、いきなり実装せず、必要な型・状態・データ・画面変更を整理します。

## 現在のコード構造

- `src/App.tsx`
  - `GameState.scene` に応じて各シーンを表示するルーター役。
  - 既存の scene 名は維持する。
- `src/game/types/index.ts`
  - `GameState`, `Item`, `Ingredient`, `Customer`, `Kebab`, `RadioBroadcast`, `MeatTower`, `ExplorationNode` を集約。
  - 現状の `Ingredient` は `taste`, `stink`, `mutation` のみ。
  - 現状の `Kebab` は `taste`, `stink`, `mutation`, `price` のみ。
- `src/game/data/index.ts`
  - 素材、アイテム、客、ラジオ、探索ノード、初期肉タワーの仮データを定義。
  - v0.4 では計算ロジックに必要な数値をここへ寄せる。
- `src/game/state/GameContext.tsx`
  - 状態初期化、画面遷移、探索、仕込み、営業、肉タワー、翌朝開始の処理がすべて入っている。
  - 現状は `makeKebab` などの計算も同ファイル内。
  - v0.4 では型安全を保つため、計算関数を小さく分けるのが望ましい。
- `src/game/scenes/*`
  - 各画面の表示と主要ボタン。
  - 現状はボタン押下で次の状態へ進むだけに近い。
- `src/styles.css`
  - 黒背景、ネオンピンク、オレンジ、黄緑の仮UI。
  - v0.4 ではレイアウトを維持し、必要な選択UIと結果表示だけ追加する。

## v0.4 で追加したいゲーム状態

### 探索

現在:

- `inventory`
- `currentExplorationNodes`
- `collectedIngredients`
- `policeAttention`

追加候補:

- `health: number`
- `stink: number`
- `cargoUsed: number` または `inventory` から算出
- `cargoCapacity: number`
- `explorationStats`
  - `health`
  - `stink`
  - `alert`
  - `cargoCapacity`
- `lastExplorationResult`
  - 取得素材
  - 体力変化
  - 臭気変化
  - 警戒度変化
  - 荷物容量変化
  - ログ文

方針:

- `inventory.length` だけでは素材の重さが表現できないため、`Ingredient` に `weight` を足す。
- `ExplorationNode` に `healthCost`, `stinkGain`, `policeGain`, `cargoPressure` などを足す。
- まずは1ノード選択で完結する。ルート線や複数ノード探索は後続。

### 仕込み

現在:

- `prepareKebab()` が `inventory.slice(0, 3)` で自動生成。
- 使用素材は `inventory` から消費されない。

追加候補:

- `selectedIngredientIds: string[]`
- `preparedKebab?: Kebab`
- `usedIngredientIds` を `Kebab` に保持
- `leftoverIngredients` は `inventory` から算出

方針:

- v0.4 では複雑なドラッグ操作ではなく、素材カードのクリック選択でよい。
- 仕込み確定時に、選択した素材から `Kebab` を作る。
- 使用素材を `inventory` から取り除き、未使用素材だけが肉タワー投入候補になるようにする。

### ケバブ性能

現在:

- `Kebab` は `taste`, `stink`, `mutation`, `price`。

追加候補:

- `umami: number`
- `spice: number`
- `stink: number`
- `addiction: number`
- `price: number`
- `tags: IngredientTag[]`
- `illegalScore?: number`

方針:

- 要件の名称に合わせて `taste` は `umami` へ寄せる。
- 既存UI互換のため、移行中は `taste` を残すか、一度に `umami` へ置換する。
- 型安全優先なら `Kebab` のプロパティを明確に置換し、参照箇所を同時修正する。
- `Ingredient` には `umami`, `spice`, `stink`, `addiction`, `basePrice`, `weight` を持たせる。
- `mutation` は肉タワーや翌朝変化向けに残してもよいが、ケバブ画面の主要指標は上記5つにする。

計算案:

- `umami = sum(ingredient.umami)`
- `spice = sum(ingredient.spice)`
- `stink = sum(ingredient.stink)`
- `addiction = sum(ingredient.addiction) + tagSynergyBonus`
- `price = 500 + sum(basePrice) + umami * 8 + addiction * 10 - stinkPenalty`

### 営業

現在:

- 全客に同じケバブを提供。
- 売上は `customers.length * kebab.price`。
- 評判は `taste - stink / 2` から単純加算。

追加候補:

- `CustomerPreference`
  - `likedTags`
  - `desiredUmami`
  - `desiredSpice`
  - `stinkTolerance`
  - `addictionSensitivity`
- `desireProgress: number` を `Customer` に追加、または `GameState.customerStates` で分離。
- `lastSalesResult`
  - 客ごとの満足度
  - 支払額
  - 評判変化
  - 警察注目度変化
  - 欲望進行度変化
  - ログ文

方針:

- マスターデータの `customers` は固定値にし、プレイ中に変わる値は `customerStates` に分離すると型安全で扱いやすい。
- ただしv0.4では小さく進めるため、`Customer` に `desireProgress` を直接足す案も可。
- 客ごとの相性計算は `src/game/state` ではなく `src/game/rules` などに分離する。

計算案:

- `tagMatch = count(customer.preferenceTags in kebab.tags)`
- `umamiScore = closeness(kebab.umami, customer.desiredUmami)`
- `spiceScore = closeness(kebab.spice, customer.desiredSpice)`
- `stinkPenalty = max(0, kebab.stink - customer.stinkTolerance)`
- `satisfaction = clamp(tagMatch * 20 + umamiScore + spiceScore - stinkPenalty, 0, 100)`
- 売上: `satisfaction >= 45` の客が購入、支払額は `price * satisfactionRate`
- 評判: 高満足で上昇、低満足や異臭過多で低下
- 警察注目度: `stink`, `illegalScore`, 警戒中の客で上昇
- 欲望進行度: `addiction` と満足度で上昇

### 肉タワー

現在:

- `feedMeatTower()` は `inventory.length * 3` を質量として追加。
- `preparedKebab.mutation > 55` なら `tentacle` へ寄る。

追加候補:

- `MeatTower.branchWeights`
  - `fat`
  - `glow`
  - `fungus`
  - `tentacle`
- `lastMeatTowerResult`
  - 投入素材
  - 系統変化
  - レベル変化
  - 不安定度変化
  - 翌朝変化候補

方針:

- `MeatTower.branch` は現在の優勢系統として残す。
- 成長傾向は `branchWeights` に蓄積し、最大値の系統を `branch` にする。
- `IngredientTag` と `MeatTowerBranch` の対応を `src/game/data` または `src/game/rules` に置く。

対応案:

- `fat`, `brain`, `sauce` -> `fat`
- `glow` -> `glow`
- `fungus` -> `fungus`
- `tentacle` -> `tentacle`
- `spice` は不安定度や警察注目度に寄与

### 翌朝変化

現在:

- `morningChange?: string`
- `log: NightLogEntry[]`

追加候補:

- `nightSummary`
  - `exploration`
  - `prep`
  - `sales`
  - `meatTower`
  - `morningChanges`
- `MorningChange`
  - `id`
  - `title`
  - `description`
  - `severity`
  - `source`

方針:

- まずは `lastExplorationResult`, `lastSalesResult`, `lastMeatTowerResult` からログを生成する。
- 後でイベント化できるよう、単なる文字列配列より `MorningChange[]` が望ましい。
- 画面上は「前夜の要約」「街の変化」「次の夜への影響」を分けて表示する。

## 実装順序

1. 型を先に拡張する
   - `Ingredient`, `Kebab`, `Customer`, `ExplorationNode`, `MeatTower`, `GameState` にv0.4で必要なプロパティを追加。
   - 既存 scene 遷移の型は変更しない。

2. データをv0.4対応にする
   - `src/game/data/index.ts` の素材、客、探索ノードに新しい数値を埋める。
   - タグから肉タワー系統への対応表を追加。

3. 純粋な計算関数を追加する
   - `src/game/rules/*` を作る。
   - まずはUIに触らず、入力と出力の型が明確な関数にする。
   - 例: `createKebabFromIngredients`, `resolveExploration`, `resolveSales`, `resolveMeatTowerGrowth`, `createMorningChanges`。

4. `GameContext.tsx` を計算関数へ接続する
   - 既存の `chooseBroadcast -> exploreNode -> prepareKebab -> completeSales -> feedMeatTower -> beginNextNight` の順番は維持。
   - 各ステップで `last*Result` を保存する。

5. 探索画面を遊べるようにする
   - ノードごとの予測変化を表示。
   - クリックしたノードで素材取得、体力・臭気・警戒度・荷物容量が変化。

6. 仕込み画面を素材選択式にする
   - 素材カード選択。
   - 選択中のケバブ性能をプレビュー。
   - 確定時に使用素材を消費。

7. 営業画面に相性判定を入れる
   - 客ごとの好み、満足度、欲望進行度を表示。
   - 営業完了時に売上、評判、警察注目度、欲望進行度を反映。

8. 肉タワー画面に余り素材投入を入れる
   - 未使用素材を投入。
   - 系統バーを更新。
   - 優勢系統とレベル変化を保存。

9. 翌朝変化ログを生成する
   - 前夜の探索、営業、肉タワー結果から `MorningChange[]` を生成。
   - `MorningScene` に一覧表示。

10. ビルド確認と手動導線確認
    - `npm run build`
    - トップ画面から `ラジオ -> 探索 -> 仕込み -> 営業 -> 肉タワー -> 翌朝変化 -> 次の夜` まで確認。

## 型安全の方針

- 計算関数は `GameState` 全体を受け取らず、必要な型だけを引数にする。
- `id` 参照は文字列のまま散らさず、変換時に `findIngredientById` などで存在チェックする。
- 結果型を作り、UIは結果型を読むだけにする。
- `undefined` を許す値は `preparedKebab?: Kebab` のように境界を明確にする。
- scene 遷移を増やす場合は `GameScene` と `nextScene` を同時に更新する。ただしv0.4では増やさない。

## 既存遷移を壊さないための注意

- `GameScene` の既存値は維持する。
- 各主要アクションボタンは残す。
- 画面ごとの完了アクションは現在と同じ順番で次sceneへ進める。
- UI選択が未完了でも、仮の推奨選択で進められるフォールバックを用意する。
- `beginNextNight` は次の夜の `radio` へ戻す。

## 未決事項

- 使用素材を仕込み確定時に完全消費するか、営業後に余りとして一部戻すか。
- 客の欲望進行度を `Customer` に直接持たせるか、`customerStates` として分離するか。
- `mutation` を残すか、`addiction` と肉タワー系統へ分解するか。
- 探索で体力が0になった場合、v0.4では営業に進めるか、その夜を失敗扱いにするか。

## v0.4 の最小到達点

- 探索で数値が変わり、素材が増える。
- 仕込みで選んだ素材からケバブ性能が変わる。
- 営業で客ごとの相性により売上と評判が変わる。
- 肉タワーが余り素材のタグに応じて4系統のどれかへ寄る。
- 翌朝画面で、前夜の結果に基づくログが読める。
- その後、次の夜へ戻れる。
